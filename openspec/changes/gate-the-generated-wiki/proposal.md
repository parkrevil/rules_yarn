## Why

The repository carries a generated wiki under `openwiki/`. Nothing checked that
it still described the code, and it did not.

OpenWiki installs a scheduled GitHub Actions workflow to refresh it. That
workflow calls a model and needs an API key this repository does not hold, so
every scheduled run failed — 36833773352 and 36981675114, both named
"OpenWiki Update", both red on `main`. A refresh that cannot succeed is worse
than none: it reports a failure nobody can act on from a checkout, and it
trains the reader to ignore a red workflow.

With nothing checking it, the wiki drifted. Fifteen citations across seven
pages now point at line ranges whose content moved or changed, and OpenWiki's
own incremental check did not flag any of them. Among them, the claim about
development-only dependencies cites `MODULE.bazel#L9-L22`, which since
`version` and `bazel_compatibility` were added spans a comment and the
`module()` block instead.

## What Changes

- `.github/workflows/openwiki-update.yml` is removed. The refresh needs a model
  and the repository has no key for one; an agent working in the repository
  already has both.
- `tools/hooks/openwiki_staleness.sh` reports whether the wiki still describes
  the repository, and refuses the push when it does not. It needs no model and
  no key: each claim in `openwiki/.claims/**` records a digest of the exact
  bytes it was written from, so the gate recomputes those digests from the
  working tree and compares. A page body cannot be regenerated by a shell
  script, so the gate reports and names what to run rather than fixing.
  `tools/hooks/openwiki_staleness_test.sh` states its contract as a table of
  fifty-six rows, most of them refusals, seven of them injected failures of a
  command the gate depends on.
- `.pre-commit-config.yaml` runs it at `pre-push`, and declares the `pre-push`
  install hook type so `pre-commit install` wires it.
- `.github/workflows/ci.yml` runs it in the `checks` job.
- `AGENTS.md` states the obligation in `## Before commit`. That rule also
  carries the correction to the OpenWiki block below it, which still claims a
  scheduled workflow refreshes the wiki: the block is written by the generator
  and restored on every run, so the repository cannot hold an edit to it.
- The wiki is regenerated in this change: eight pages, fifteen re-anchored
  citations, and a new `operations/publishing.md` for the release and registry
  apparatus added by `publish-to-the-registry`, which had no page.
- `close-the-verification-gate`'s task 2.3 is closed with what the CI
  measurement reported. The work was done and never recorded.

## Capabilities

### Modified Capabilities

None. Nothing here changes what the ruleset does or how a consumer uses it.
`.openspec.yaml` sets `skip_specs: true`.

## Impact

- New `tools/hooks/openwiki_staleness.sh` and
  `tools/hooks/openwiki_staleness_test.sh`.
- `.pre-commit-config.yaml`, `.github/workflows/ci.yml`, `AGENTS.md`.
- Removed `.github/workflows/openwiki-update.yml`.
- `openwiki/` regenerated, including its claims sidecars, which OpenWiki writes.
- `openspec/changes/close-the-verification-gate/tasks.md`.
- No Bazel rule, no public API, no pin.
